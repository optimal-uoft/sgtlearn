## Suspicions

### sgtlearn-base-py--resolve-pairwise-candidates

Logical mistakes: No outright errors on the main path. Integers are treated as absolute counts and floats as fractions of n_features, rounded up, which matches the usual sklearn convention (like max_features). One subtle risk: the float product is taken with no tolerance, so floating-point error can push the result up by one when value * n_features should be an exact integer (e.g. 0.07 * 100 evaluates to 7.000000000000001, which rounds up to 8). The intended result is the mathematical ceiling of value * n_features.
Robustness omissions: (1) Nothing caps the result at n_features. An int larger than n_features, or a float above 1.0, gives a count bigger than the number of features that exist. It is unclear whether the helper or its callers are meant to clamp this. (2) n_features is not checked (for example, a negative value would give a negative result for a positive fraction). As a private helper it can assume a non-negative int. (3) Bools, including numpy bools, are correctly rejected. NaN and +/-inf are correctly rejected. numpy integer and floating scalars are accepted, as they should be.
