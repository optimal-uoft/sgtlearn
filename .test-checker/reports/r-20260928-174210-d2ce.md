## Suspicions

### sgtlearn-features-py--resolve-column-index

Logical mistakes:
- Integer detection relies on the built-in int type alone. NumPy integer scalars (e.g. np.int64(2), which you get when iterating over a NumPy array of indices) are not Python ints, so they fall through to the column-name branch. They then fail with a misleading "requires a pandas DataFrame" or "column name ... not found" error, even though they are valid positional indices.
- bool is a subclass of int, so True and False are silently accepted as positions 1 and 0. A boolean is almost certainly a user error, not a column reference.
- Duplicate column names: the name-to-position lookup keeps the last occurrence, so a duplicated name silently resolves to one arbitrary position instead of being reported as ambiguous.
- A name can resolve to a position >= n_features when column_names is longer than the number of features. The name path never checks the result against n_features, while the integer path does.

Robustness omissions:
- No type check. Values that are neither integers nor strings (floats, None, lists) are treated as column names and give a confusing "not found" or "requires DataFrame" message instead of a clear invalid-type error.
- No check that column_names is consistent with n_features.
- Negative indices are rejected (no Python-style wrap-around). This looks deliberate and should be kept, with a clear out-of-range error.
