## Suspicions

### sgtlearn-multioutput-py--label-encoders-as-list

Logical mistakes: none found. A single encoder is only accepted when n_outputs == 1. When there are several outputs it is rejected, not copied to every output. That is correct: each per-output encoder is fitted on that output's own classes, so reusing one encoder across outputs would decode labels wrongly. The dedicated "got 1" error for this case is redundant with the general length check, but it does no harm and gives a clearer message.
Robustness omissions: (1) n_outputs is not validated. With n_outputs <= 0 or a non-integer value, an empty list/tuple is returned as a valid empty result when n_outputs == 0, and other inputs get confusing "expected 0/-1 label encoders" messages. It should require a positive integer. (2) Only list and tuple count as sequences. Other containers, such as a numpy object array of encoders, are wrapped as one "encoder" and then fail the length check with a misleading message. This is acceptable if documented. Strings must never be split into characters. (3) Elements are not checked, so None entries (or a scalar None) pass through silently. This is acceptable because type checking belongs to the caller, but it should be documented.
