## Suspicions

### sgtlearn-export-py--plot-tree

Logical mistakes:
- `proportion` is documented ("display sample proportions instead of counts") but never used. It is not forwarded to leaf or panel rendering, so `proportion=True` has no visible effect.
- `X` is documented as supplying "node sample counts", and samples are routed through the tree, but the routed reach is only used for internal-panel histograms and marginals. Leaf text never receives the per-node counts or proportions computed from `X`, so leaves never show counts derived from `X`.
- The feature-name caption next to every internal panel is always drawn, whatever `label` says. If `label` follows the sklearn-style convention of controlling field-name labels (for example "none"), the caption should obey it.
- The automatic figure size is estimated from the full tree (all leaves, deepest depth) rather than from the tree truncated at `max_depth`. A truncated plot therefore gets an oversized figure. This is cosmetic, not a correctness break.
Robustness omissions:
- There is no validation of `max_depth` (a negative value should be rejected), `precision` (must be >= 0), `n_hist_bins` (must be >= 1), `node_aspect_ratio` (must be > 0; zero causes a division by zero), `fontsize` (must be positive if given), or `label` (unknown values are silently accepted).
- An explicit `class_names` list is not checked against the number of classes. A shorter list can cause index errors or wrong labels.
- An explicit `feature_names` is not checked against `n_features_in_`. A shorter list causes an IndexError deep in rendering, not a clear ValueError.
- `class_names` given for a regressor is silently ignored. This is acceptable, but it should be documented.
- If the exported tree has no nodes, `max()` over an empty sequence raises an opaque error.
- Non-numeric `X` raises only whatever error float conversion produces. It is not re-raised as a clear ValueError.
