## Suspicions

### sgtlearn-weights-py--validate-sample-weight-array

Logical mistakes: none on the normal path. Length, negativity and "at least one positive" are checked in a sensible order, and the error messages match the conditions. One consequence of the checks: NaN fails both `sw < 0` and `sw > 0`, so NaN entries are never flagged as invalid. An array like [1.0, nan] passes. An all-NaN array is rejected only because it has no positive value, and the message ("must contain at least one positive value") gives the wrong reason.
Robustness omissions:
- Dimensionality is never checked. Only shape[0] is compared, so a 2-D array of shape (n_samples, k) is accepted even though the message says the shape must be (n_samples,). A 0-d (scalar) array raises IndexError instead of ValueError.
- Non-finite values are not rejected. NaN gets through (see above), and +inf passes as a "positive" weight. Either one would corrupt later weighted sums or normalisation.
- dtype is never checked. Non-numeric input (object or string arrays) would fail with a TypeError from the comparison instead of a clear ValueError.
- Empty input (n_samples == 0, sw of length 0) is correctly rejected by the "at least one positive" check. That behaviour should be kept.
