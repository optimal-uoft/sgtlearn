## Suspicions

### sgtlearn-base-py--identitylabelencoder

Logical mistakes:
- `transform` is meant to be the identity map onto integer class indices, but it never checks that the values are valid indices into `classes_`. A fitted sklearn `LabelEncoder.transform` raises `ValueError` for labels it has not seen. Here, negative values, values >= n_classes, and non-integral floats (1.7 is truncated to 1 by the int64 cast) all pass through silently as wrong codes. That breaks the "same sklearn contract" the class docstring promises.
- The identity mapping is only consistent with `inverse_transform` when `classes_` is exactly `0 .. K-1`. The constructor accepts any array, so a caller could pass, for example, `["a", "b"]`. Then `transform` would try to cast strings to int (or return codes that do not match), while `inverse_transform` would return strings. Nothing enforces or checks the documented precondition that `classes_ == arange(K)`.
- `fit_transform`, inherited from `LabelEncoder`, does not go through `fit`. It recomputes and overwrites `classes_` from `y`, so it gets around the "preset classes, do not fit" guard that `fit` enforces.

Robustness omissions:
- No validation of `classes_` at construction: it should be 1-D and should equal `arange(K)`, or at least contain integer values.
- No shape validation in `transform`: sklearn accepts 1-D or column-vector input and rejects multi-column 2-D input. Here, flattening accepts any shape.
- No range or integrality check in `transform`. Non-numeric input only fails through a raw cast error, not a clear `ValueError`.
- Empty input should return an empty int64 array. This works today, but nothing states it.
