## Suspicions

### sgtlearn-export-py--route-samples

Logical mistakes:
- The docstring says the result maps node ids to "column-indices", but the values are row indices of X (sample indices). That is a documentation error. The intended meaning is row indices.
- In the numeric-threshold branch, the bin index is computed against the raw threshold list, while the bin-to-partition table comes from the finite-routing normalisation helper. If that helper changes the number or order of bins (for example by dropping non-finite sentinel thresholds or merging bins), the searchsorted bin index and the partition table can fall out of alignment. Clamping to the last bin hides the mismatch and can route samples to the wrong child. Bin lookup and partition table should both come from the same normalised binning.
- Samples are assigned to children by comparing the partition index with each child's position. If a partition index is negative or not less than the number of children (a malformed bin_to_partition or nan_prediction_partition), those rows go to no child and silently disappear. That breaks the stated promise that the leaves' sample sets partition the root's samples.
- A numeric node with no "feature" key (feature is None) does not raise a clear error. The column lookup broadcasts or indexes incorrectly.
Robustness omissions:
- X is not checked to be 2-D. A 1-D input or a scalar fails with obscure indexing errors instead of a clear ValueError.
- Feature and column indices are not bounds-checked against X's column count.
- Non-numeric (object or string) X makes the finiteness test raise a TypeError with no helpful message.
- If a child id is missing from the node list, or root_index names an unknown node, a bare KeyError is raised. There is no check for duplicate node ids.
- With zero rows (n == 0), every node should get an empty array. This happens, but only because of the empty-rows shortcut.
- The FIFO queue uses list.pop(0), which is O(n) per pop. This is a minor efficiency issue, not a correctness bug.
