## Suspicions

### sgtlearn-multioutput-py--encode-classification-targets

Logical mistakes: none found. The fit path fits one fresh LabelEncoder per output column and returns per-output encoded columns, the fitted encoders, their classes_ and class counts. The transform path uses the supplied encoders only for transform, never refitting them, and reports the classes from those encoders. It does not re-derive them from y. Either way the encoded matrix is always 2-D with shape (n_samples, n_outputs), including for 1-D input, and the four returned lists are all of length n_outputs and aligned by output index.
Robustness omissions: (1) Validation is delegated to helpers and is not stated in the contract: as_output_matrix handles bad shapes, and label_encoders_as_list checks the number of encoders against n_outputs. The spec should require a ValueError when the number of supplied encoders does not match the number of outputs, and when a lone encoder is given for multi-output y. (2) Labels in y that a supplied encoder never saw make LabelEncoder.transform raise ValueError. This is correct behaviour, but it should be documented. (3) Supplying an unfitted encoder raises sklearn's NotFittedError. This should be documented, not silently tolerated. (4) Degenerate inputs are not guarded. A 2-D y with zero output columns gives an empty column list, and stacking it fails with an unclear error, so a clear ValueError is expected. With zero samples, the fit path yields encoders with empty classes and zero class counts. (5) Supplied encoders are returned as-is (the same objects, not copies), and a single encoder is returned wrapped in a one-element list. Callers rely on this, but it is implicit.
