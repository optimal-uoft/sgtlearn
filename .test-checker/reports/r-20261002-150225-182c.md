## Suspicions

### sgtlearn-base-py--sgtclassifier-fit

Logical mistakes:
- `tao_n_runs` is never validated. It is only compared with `> 0`, so a negative value, NaN, or a bool is quietly treated as "do not run TAO" and fit succeeds. The stated intent lists tao_n_runs among the checks that run before training. An invalid value should raise ValueError before any work is done, not change behaviour without warning. A non-integer positive value (e.g. 2.5) is passed straight to refinement. It can only be rejected there, after the full tree has already been trained. The state restore makes this correct, but it is not the "validate everything first" behaviour the intent describes.
- `check_input=False` path: the single-output test looks at the type of `classes_`, not at its shape. If a caller presets one output's labels as a plain list (e.g. `classes_=[0, 1]`, `n_classes_=2`), each label is treated as a separate output's class array, and iterating over the integer `n_classes_` then fails with a TypeError. The caller should get a clear ValueError instead. Nothing checks that the number of preset class arrays and n_classes_ entries matches the number of output columns in y. Nothing checks that each n_classes_ entry equals the length of its class array.
- Everything else gets the order right. All input, weight, feature and hyper-parameter checks and the native training run before `self` is touched. On a TAO failure, a shallow copy of the previous attribute dict is restored, so the previous fitted objects are themselves restored (the same objects, not copies) and predictions stay the same. A never-fitted model goes back to unfitted.

Robustness omissions:
- `inner_min_impurity_decrease` (and the integer hyper-parameters such as num_partitions, min_samples_leaf, the depth/leaf limits, coordinate_descent_* and random_state) get no explicit finite/non-negative or range check, unlike the three outer penalties. A bad value is only caught by a native-side error or a raw `int()`/`float()` conversion error, if at all. Because this all happens before any attribute is assigned, the model state stays safe, but the error messages are unclear.
- `tao_lambda` is only checked inside refinement, after training. The restore keeps this safe, but the bad value is found late.
- With `check_input=False`, X is not checked to be 2-D. That is acceptable by contract, but a 1-D X gives an IndexError instead of a ValueError.

### sgtlearn-base-py--sgtregressor-fit

Logical mistakes: none found on the happy path. The new tree is trained into locals. A shallow snapshot of the instance state is taken before any fitted attribute is assigned, and that snapshot is restored if TAO refinement raises. The previous `_est`, `_processed_features`, `n_outputs_`, `n_features_in_`, `feature_names_in_` and `_tao_refined_` objects therefore survive a failed refit. A never-fitted model goes back to the class-level defaults.

Robustness omissions:
1. `tao_n_runs` is never validated, although the stated intent lists it among the checks that must run before anything is assigned. The code only evaluates `tao_n_runs > 0`, so:
   - a negative value (for example -1) or NaN silently disables TAO instead of raising;
   - a non-integer float (for example 2.5) or a bool gets through and is passed to TAO, where it fails late, after a full tree fit, or is quietly truncated;
   - a non-numeric value raises an uninformative TypeError from the comparison.
   A correct version rejects anything that is not a non-negative integer with a ValueError (or TypeError), before training.
2. `tao_lambda` is not validated up front either; it is only checked, if at all, inside TAO after the tree has been trained. The rollback keeps state consistent, but the bad value is found late. It should be finite and non-negative and checked before training. This is minor because it is outside the developer's stated list.
3. The penalty check accepts `bool` because bool is a subclass of Real, so `True` and `False` pass as 1.0 and 0.0. Minor.
4. Nothing is lost on rollback: the snapshot is a shallow copy of the attribute dict taken before assignment, and TAO only mutates the newly created tree, not the previous one. No issue.

### sgtlearn-base-py--as-native-y

Logical mistakes: none found. The conversion runs with float overflow warnings silenced, so a finite value too large for float32 becomes infinity without a RuntimeWarning. The infinity check after the cast then catches both real infinities and overflowed finite values, and the error message names float32, as the stated intent requires.

Robustness omissions: (1) NaN is not rejected. This matches the sibling `_as_native_X`, which rejects only infinity and overflow, so NaN is presumably caught by earlier sklearn validation. It should be stated as a precondition rather than silently assumed. (2) The helper being called is typed to take an ndarray (`y_enc: np.ndarray`), but this function accepts `Any`. Lists, tuples, column vectors and integer arrays must still come out as the documented 1-D or 2-D C-contiguous float32 array. Whether they do depends on how the helper coerces its input. (3) A finite value that overflows float32 is reported with the same ValueError as a real infinity, so the two cases cannot be told apart. This is acceptable because it matches the stated intent. (4) Empty y is not handled specially. The call should return an empty float32 array of the right rank, or leave the error to upstream validation, and must not crash in an unexpected way.

### sgtlearn-ensemble-random-sgforest-regressor-py--randomsgforestregressor-check-x-y

Logical mistakes: none found. Both conversions run before the method returns, so nothing on the estimator changes when either one fails. The float32-range check on y runs on the full validated target array, not on bootstrap samples. That means a row that overflows float32 is rejected even when no tree's bootstrap sample would draw it, which is what the developer asked for. The result of the y check is thrown away on purpose, so the caller gets the float64-validated y as stated. The upstream validator already rejects infinity in X and both NaN and infinity in y (multi-output y is always required to be finite). The only new rejection this method adds is a finite value that is too large for float32.
Robustness omissions: (1) The stated intent says the returned y is float64, but the validator only converts object-dtype targets. Integer or boolean y comes back in its original dtype, not float64. Callers that assume float64 may get a different dtype. (2) NaN in X is allowed and passed through to the float32 X. This seems intended, since the trees presumably handle missing values, but it should be stated as part of the contract. (3) A column-vector y of shape (n, 1) is kept 2-D, not flattened. Downstream code has to handle both 1-D and 2-D targets. (4) sample_weight is not validated here. That belongs to fit, so it is out of scope for this method.

### sgtlearn-tao-py--prepare-tao-arrays

Logical mistakes: none found on the happy path. One inconsistency: the number of samples used to size the default and normalized sample weights comes from the raw `X` argument, not the validated float32 array. For ndarray input the counts are the same. For array-like input such as a nested list, `X.shape` does not exist, so the call fails with AttributeError instead of working or raising a clear ValueError. The sample count should come from the validated X.

Robustness omissions:
- X's column count is never checked against the model's fitted `n_features_in_`. Only whether the attribute exists is checked. A refit X with the wrong number of features would silently produce arrays that do not match the fitted trees. It should raise ValueError, unless a validation step before this always enforces it.
- For classification, y's number of output columns is never checked against the fitted `n_outputs_`. For regression, it is never checked against the fitted output count.
- y labels the fitted encoders never saw are rejected only if the downstream encoder rejects them. The contract should state that this raises ValueError.
- The length, finiteness and non-negativity of sample_weight are left entirely to the normalization helper. The contract should guarantee a ValueError for a length mismatch and for invalid weights, in both the class_weight path and the plain path.
- The effective weights from the class_weight path are not guaranteed to be float32, while the plain path guarantees float32.
- The fitted check runs only after X/y validation, so an unfitted model given bad X reports a shape error instead of NotFittedError. This is acceptable but should be documented.

### sgtlearn-tao-py--validate-x-y

Logical mistakes: None that break the happy path. The fitted check, the sparse rejection, the feature-count check, the sample-count check and the output-count check (1-D y counts as one output) all match the stated intent. One small flaw: the output count is read from the second axis whenever y has more than one dimension, so a 3-D (or higher) y is silently treated as having y.shape[1] outputs instead of being rejected.
Robustness omissions:
- y with ndim > 2 is never rejected. A shape like (n, k, m) passes when k equals the fitted number of outputs.
- For classifiers (and for every model when check_input=False), y is only converted with asarray. Nothing checks that y contains no NaN or that it is a valid label array. For regressors with check_input=True, sklearn already rejects infinite y and the extra check rejects NaN, which matches "finite numeric targets". With check_input=False nothing is enforced, which is acceptable only as a deliberate fast path.
- With check_input=False, X is not converted to float64 and its dtype is not checked. A non-numeric (object or string) 2-D X with the right shape is accepted.
- fit now rejects finite X values that overflow float32 (recent commits). This validator has no such check, so refinement can accept X that fit would have rejected. This is inconsistent with the fit path.
- n_outputs_ values of 0 or None quietly fall back to 1 instead of being treated as a malformed fitted state. This is minor.
