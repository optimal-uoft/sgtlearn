## Suspicions

### sgtlearn-base-py--sgtclassifier-fit

Logical mistakes: No definite happy-path errors. There are three questionable behaviours:
(a) Zero is used internally to mean "no limit". So an explicit max_depth=0, max_leaf_nodes=0, inner_max_depth=0 or inner_max_leaf_nodes=0 is silently read as "unlimited" instead of being rejected.
(b) random_state=None is mapped to a fixed seed of 42. That makes fits deterministic instead of following the scikit-learn meaning of None ("use fresh randomness"). This appears to be intentional, since the default is also 42, but it is worth documenting.
(c) With check_input=True, the fitted class attributes (classes_, n_classes_, n_outputs_) are written before the "at least two classes per output" check. A failed fit therefore leaves the estimator partly changed.

Robustness omissions:
- Only min_impurity_decrease, pairwise_penalty and branching_penalty are checked for being finite and non-negative. inner_min_impurity_decrease, tao_lambda, min_samples_leaf, inner_min_samples_leaf, num_partitions, coordinate_descent_max_iters, coordinate_descent_patience and tao_n_runs are not checked for sign, type or finiteness. A negative tao_n_runs silently turns refinement off.
- The finiteness check accepts booleans, because bool counts as Real.
- With check_input=False, X is not checked for being 2-D, for being empty, or for a numeric dtype. If classes_ was never set as an attribute, the call may fail with AttributeError instead of the intended ValueError.
- With check_input=False, the number of preset class entries is not checked against the number of outputs.
- The length of sample_weight must match n_samples, and weights must be finite and non-negative. This is only enforced if the helper does it.
