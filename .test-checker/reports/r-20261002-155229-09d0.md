## Suspicions

### sgtlearn-ensemble-random-sgforest-py--randomsgforest-fit

Logical mistakes: none found on the happy path. All fitted attributes are rebound to new objects rather than changed in place, and the attribute dictionary is restored in one step, so a shallow snapshot is enough to roll back. Tree seeds are drawn before any tree is fitted, which keeps results the same whether trees are fitted one at a time or in parallel.
Robustness omissions: (1) n_estimators is only checked with "< 1". A non-integer value (for example 2.5, or True) gets past that check and is quietly truncated. A value that cannot be compared (None, a string) raises TypeError rather than a clear ValueError. These checks run before any state changes, so the rollback promise still holds. (2) When random_state is a RandomState instance, a failed fit has still used up random draws from it. Only the forest's own attributes are restored, not the generator's internal state. (3) The rollback relies on helper steps (_check_X_y, _prepare_sample_weight, the tree factory) never changing an existing fitted attribute in place, for example classes_ or processed_features_. If one did, the shallow snapshot would not undo it. (4) If one tree fails during a parallel fit, trees on other threads may still be running when the error propagates. Their results are thrown away, so this is acceptable.
