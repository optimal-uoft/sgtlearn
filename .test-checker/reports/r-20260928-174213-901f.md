## Suspicions

### sgtlearn-weights-py--per-class-multiplier

Logical mistakes: none found on the happy path. The method builds a weight per class, where classes missing from the mapping default to 1.0 (as in scikit-learn). It checks that each key is a known training class and that each weight is non-negative, then gathers one weight per sample using the encoded labels.
Robustness omissions:
- Non-finite weights are not rejected. NaN passes the "< 0" check because comparisons with NaN are False, and +inf also passes. Either value then silently corrupts every downstream sample weight. The intended contract "class weights must be valid non-negative numbers" should reject NaN and infinity with ValueError.
- Encoded labels are not validated. A negative code silently wraps around to a class counted from the end. A code >= n_classes raises a raw IndexError. A non-integer array fails with an unclear error. Codes should be integers in [0, len(classes_o)); anything else should raise ValueError.
- Weight values that cannot be converted to float (for example None or a non-numeric string) produce a raw TypeError or ValueError from the conversion, not a clear class_weight error.
- Duplicate entries in classes_o would silently map a label to its last position. This is a precondition, not something the method must check.
