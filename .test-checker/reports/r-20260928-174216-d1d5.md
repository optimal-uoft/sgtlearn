## Suspicions

### sgtlearn-ensemble-random-sgforest-py--n-samples-bootstrap

Logical mistakes: none found on the main path. None returns n_samples. An integer is checked to lie in [1, n_samples] and is returned unchanged. A fraction is checked to lie in (0.0, 1.0] and is converted to max(1, round(fraction * n_samples)), which can never be larger than n_samples. This matches the scikit-learn convention for the max_samples parameter of a bootstrap. Note that Python's round() uses round-half-to-even, so for example 0.5 * 5 = 2.5 rounds to 2. That is consistent with scikit-learn and is accepted behaviour here.
Robustness omissions:
(1) Booleans are kept out of the integer branch, which is correct, but they then fall into the float branch. True is quietly treated as 1.0 and returns n_samples. False raises the float-range error, whose message is misleading. A bool is not a meaningful max_samples, so it should be rejected outright.
(2) Any value that float() can convert is accepted, including numeric strings such as "0.5" and objects with a __float__ method. Only real numbers (and None) should be allowed. Anything else should raise an error instead of being coerced.
(3) n_samples is never checked. If n_samples is 0 or negative, the float branch still returns at least 1, which is more than the number of available samples. n_samples should be a positive integer.
(4) NaN and infinite floats are correctly rejected by the range check, and this should stay that way.
